# Handoff: Athenaeum — Independent University Platform

## Overview
Athenaeum is an online school that runs full degree programs (bachelor's, master's, certificates). Lectures, practice, and tutoring are generated by AI from an **approved set of sources** for each course. Assessment is done by **named human reviewers** using **fixed rubrics**, with **recorded oral defenses**. The school is **not accredited**. Its credential is worth something because every grade, paper, and AI interaction can be inspected by the public.

The product is built on four ideas. Every screen expresses at least one of them:
1. **Every claim can be traced to a source.** Any statement in a lecture, tutor answer, or quiz links to the exact source passage. Where the sources disagree, the claim is marked as disputed.
2. **Proof of authorship.** The platform records the writing process (notebook → outline → drafts → tutor sessions → submission) as an "authorship receipt" that stays attached to the work.
3. **Lectures you can interrupt.** The learner can stop a lecture at any moment to ask for a simpler version, more depth, an example, the opposing view, or a comprehension check. Every answer cites the course sources.
4. **Discussion structured like a seminar, not a social feed.** Posts must contain a claim, the evidence for it, and the strongest objection. A facilitator replies using only the course sources.

The prototype covers 9 screens: **Catalog** (public program browser + program detail), **Dashboard**, **Program** (degree audit + full ordered schedule), **Course**, **Lecture**, **Reading**, **Essay**, **Records** (gradebook / transcript / outcome mastery), and **Portfolio** (public dossier).

`reference/original-product-spec.md` is the founder's full written product description (23 functional areas). It is the source of truth for scope beyond these 9 screens.

## About the design files
`prototype/Athenaeum.dc.html` is a **design reference built in HTML**: a clickable prototype that shows the intended look, content, and behavior. **It is not production code.** Rebuild these designs in the target codebase's existing stack, using its own patterns and libraries. If there is no codebase yet, choose a suitable stack. Recommended: Next.js (App Router) + TypeScript + a CSS approach that can carry the tokens below (CSS variables / Tailwind theme). Use Postgres for the program, course, grade, and authorship-log data, plus an LLM integration layer that only answers from retrieved course sources.

To view the prototype, open `prototype/Athenaeum.dc.html` in a browser with `support.js` alongside it. The file holds a markup template plus a logic class (`class Component`) inside a `<script data-dc-script>` tag. All demo data lives in that class: `catalog()`, `courseInfo()`, `answers()`, `claims()`, `quotes()`, and the arrays in `renderVals()` / `catalogVals()`. Treat that data as the **seed-data spec**.

## Fidelity

## Responsive behavior
Everything is fluid with no fixed-width containers. Layouts use flex-wrap with `flex: 1 1 <basis>` columns (main ~520–580px basis, sidebar ~290–300px basis) and `grid-template-columns: repeat(auto-fit, minmax(…, 1fr))`. Below ~900px, sidebars drop under the main column. The gradebook table scrolls horizontally (min-width 620px). Headline sizes use `clamp()`. On mobile, the header nav should become a scrollable tab strip or bottom tab bar, and the Lecture player stays at the top of the screen.

- **Hero:** label "CATALOG OF PROGRAMS · 2026–27". H1: "A full course of study, every step of it in the open." Lede promises that every class, its order, syllabus, and time requirement are visible before enrolling. On the right, a disclosure with a 2px left rule: not accredited, independent credential backed by a public record.

### 2. Catalog, program detail
- "← All programs" back link.
- **Header:** level · intake, H1 program name, summary. Stat strip in a bordered box: LENGTH / TERMS / COURSES / CREDITS / WEEKLY hours.

### 6. Lecture player (interruptible, source-grounded)
- **Dark player card** (`#1C1A17`): course/module/lecture label, PLAYING/PAUSED state, serif title and subtitle. A 52px round play/pause button (`#EAF1EC`). Progress bar + clock (`mm:ss` / 42:00). Speed (1.0×) and BOOKMARK buttons.
- **"Interrupt the lecture"** offers 5 actions: *Say that more simply · Go deeper · Give me an example · Who disagrees? · Check I understood*. Clicking one **pauses playback** and opens an **answer panel** (accent tint, attached under the player) containing: "Paused at {clock} · {mode label}", a serif title, two paragraphs, a "Drawn from" list of 2 citations, and "Resume lecture ↻" (which resumes playback and closes the panel).
- **Transcript:** timestamped paragraphs in serif. Inline **source marks** (S1, S2 = accent chip; S3 = caution chip for *disputed*) open the **Claim inspector** in the sidebar and highlight their paragraph (`#FBF8F1`).
- **Claim inspector** (2px accent border card): ID, **status line** (e.g. "CORROBORATED · 2 SOURCES AGREE" / "SUPPORTED · READING IS CONTESTED" / "DISPUTED · THE CORPUS DISAGREES" in caution), source title, location · type (PRIMARY · ARCHAEOLOGICAL, etc.), quoted excerpt, a plain-language note on what the claim does and doesn't rest on, and buttons "Open in reader" (→ Reading) and "Save to notebook". ✕ closes it.
- **Sidebar:** Notes at timestamps (existing notes + a textarea that stamps new notes to the current time). An in-lecture **Knowledge check** (multiple choice). A "Recorded this session" transparency note.
- **Production behavior:** use real audio/TTS with the transcript synced to playback. Interrupt answers come from retrieval over the course's approved sources only. If the sources can't support an answer, say so explicitly. Log each interruption and each inspected source to the authorship record.

### 7. Reading & annotation workspace
- **Left column:** source metadata card (title, author, publisher, TYPE / ACCESS / REVIEWED). Chapter section list showing done (struck through), current (accent), and upcoming. Note: "Sections count as read when you've worked through them — not when the page opens."
- **Center:** reader page with section label, serif H2, and body in Newsreader 18px/1.85. **Highlightable passages** (green highlight = supports, ochre = complicates) are clickable. Actions: Ask about this passage · Compare with EA 35 · Five questions on §5 · Mark §5 worked through.
- **Clicking a passage** opens a **New annotation** card in the right column: the quoted text, a note textarea, **tag chips** ("THESIS 2 — DEPENDENCY", "MODULE 4", "COMP. ESSAY"), an **automatically generated Chicago-style citation**, and "Save to research notebook" (increments the notebook count and closes the card).
- **Research notebook:** saved quotes, each with a tag label (accent/caution/neutral) and a mono citation. Tagged quotes appear in the Essay screen's "Evidence to hand".

### 8. Essay workspace + AI-use declaration
- Header: course · module · category weight, title, word limit, due date, revision and defense policy.
- **Prompt** box with constraints (SOURCES · OUTSIDE SOURCES · OUTCOMES).
- **Editor:** large serif textarea. The header shows draft version, saved time, and a **live word count** "N / 1500 WORDS" (turns caution when over the limit). Toolbar: Insert citation from notebook · Where does this need evidence? · Outline view.
- **AI use declaration** (Level 2 policy): four toggle rows with checkboxes. Three permitted uses show their **logged evidence** (e.g. "3 logged tutor sessions · 41 min total"). The fourth, "Generated prose appears in my submission", is styled in caution. **If checked**, a warning panel appears and the submit button changes to "Submit to integrity review". Submission is never blocked, and the draft history is attached. Below that: a public statement textarea ("published with the paper"). Submit changes to "Submitted ✓" with the note "Receipt sealed. One revision remains."
- **Sidebar:** **Rubric, locked** (5 criteria with points and one-line descriptors: Thesis 25, Primary evidence 25, Counterargument 20, Citation 15, Prose 15). **Evidence to hand** (notebook quotes with CITE actions + "Open notebook" link). **Authorship receipt**, a vertical timeline (left rule) of timestamped process events ending in a greyed "PENDING" step.

### 9. Records
Tabs (underline style): **Course gradebook / Program transcript / Outcome mastery**.
- **Gradebook:** a table (Assignment, Category, Status, Score, Evidence link). Status colors: GRADED accent, LOCKED label grey, DRAFT caution. Ungraded rows are tinted. Each evidence link goes to its artifact (ITEMS / RUBRIC / POSTS / RECEIPT). "REVISED" tag where applicable. Below: **Rubric history**, which flags the weakest dimension across papers and ties it to the upcoming essay, and **"If Friday goes well"**, a grade projection labeled "Projection, not a promise".
- **Transcript:** a formal, document-style "Record of Study" page with a centered header, "UNOFFICIAL · GENERATED {date} · NOT AN ACCREDITED DEGREE", terms with course rows (code, title, credits, grade), in-progress grades marked with *, a footnote on grade locking and appeals, credit and index totals, and buttons "Export dossier (PDF)" and "Public verification page".
- **Outcome mastery:** each learning outcome gets a %, item count, a strength label, a 5px bar (caution below 70%), and an optional coaching note.

### 10. Portfolio (public dossier)
- **Hero:** URL label "athenaeum.study/ada-reyes", serif name, plain statement of progress, chips (PUBLIC · VERIFIABLE, INDEX, counts), and a **Credential status** box (not accredited + "VERIFY THIS RECORD →").
- **"Claims, and the evidence under them":** expandable claim cards (INSPECT → / CLOSE ✕).
  - Course claim: WHAT WAS DONE / HOW IT WAS SCORED / WHO CHECKED IT + artifact buttons.
  - Paper claim: thesis quote + PROCESS / AI USE, DECLARED / EVALUATION (including the before/after revision score).
  - **Transparency record:** a full accounting of AI involvement (lecture hours, tutor sessions, papers with generated prose 0 of 4, defenses, integrity flags and their outcomes).
- Bottom grid: **Written work** list, **What reviewers said** (attributed quotes), and **What this page controls** (per-artifact visibility: PUBLIC / LINK ONLY / PRIVATE). Viewers are always told when something is withheld.

## Core data model (suggested)
Program → Terms (ordered) → Course slots (course | concentration | elective) → Course → Modules (ordered) → Items (lecture, reading, quiz, seminar, assignment). Course ↔ **ApprovedSource** (license/open, reviewer, date). Lecture → Segments (timestamp, text) → **Claims** (sourceId, location, excerpt, status: corroborated / supported / disputed, note). Assignment → **Rubric** (locked_at) → Criteria. Submission → Drafts (versions), **AuthorshipEvents** (type, timestamp, payload), **AIDeclaration**, Evaluations (reviewer, per-criterion scores, comments), Defense (recording). Learner → Enrollments, Grades (locked flag), OutcomeMastery (per item), Notebook entries (quote, tags, citation), Visibility settings per artifact. Reviewer/Provenance badges (what, who, credential, date).
